W4A16 Python Reference 与 HMX Native Drain 对齐报告

仓库：qcom_htp。基于设备 probe，更新日期：2026-05-14。下方 probe 证据为按需重新生成，非仓库存档。

最终结论： W4A16 custom kernel 与 QNN native output 已经对齐。之前 Python reference 不对齐的根因不是 weight packing、layout、custom wrapper 或 native oracle 错，而是 Python 少模拟了 W4A16 HMX 在 cvt.uh drain 前对 accumulator 做的 256 粒度有符号向下取整。

1. 问题定义

旧 Python reference 使用的公式是高层量化直觉：

acc = (A_u16 - 32768) @ W_i4
out = saturate_u16(round(acc / 7 + 32768))

这个公式能解释大方向，但不能 bit-exact 模拟 QNN native/HMX。单层时误差只有 0..36 个 U16 code；chain8 中这些小误差被反复送回后续 MatMul，最终在饱和边界放大成 0 和 65535 的差异。

2. 正确的 W4A16 HMX Drain 模型

设备 probe 证明当前 v75 + QNN 版本的 W4A16 HNH path 需要以下模型：

acc = (A_u16 - 32768) @ W_i4
acc_hmx = floor(acc / 256) * 256
out = saturate_u16(round(acc_hmx / 7 + 32768))

这里的 floor 是算术向下取整，不是 toward-zero truncation。对于负 accumulator，它会继续向更小的 256 边界走。例如 acc=-1 会变成 -256。

为什么 k_impulse 能证明这一点

构造 A=32768+1 的单 K impulse 时，旧公式会输出 32768 + round(W/7)。HMX 实际行为是：

weight_i4旧公式趋势HMX floor256 后实际输出
W < 0接近 32767 或 32768floor(W / 256) * 256 = -256round(-256 / 7 + 32768) = 32731
W >= 0接近 32768 或 32769floor(W / 256) * 256 = 032768

设备输出正是这个模式：负权重 lane 输出 32731，非负权重 lane 输出 32768。同时 zp probe 证明零 accumulator 会输出 32768，排除了固定 baseline 偏移。

3. 代码变更

修正点在 example/qnn_hmx_matmul_common/gen_quant_chain.py 的 reference_contract == "native" 分支中，仅对 w4a16 启用：

if family.name == "w4a16":
    acc = (cur.astype(np.int64) - 32768) @ w_raw_kn.astype(np.int64)
    acc = np.floor_divide(acc, 256) * 256
    y = acc.astype(np.float64) / 7.0
    return np.clip(np.rint(y + 32768.0), 0, 65535).astype(np.uint16)

没有把这个规则套到 W8A16/W16A16。它们同属 A16 输出路径，但权重位宽、control constants 和 kernel family 不同，需要单独 probe 证明。

5. 如何复现

本节的证据全部按需重新生成，不在仓库中存档。chain1 / floor256 / native-chain1 probe 都由 W4A16 per-channel chain1 correctness gate 产生，它本身就是 floor256 drain 的回归门：

# default / zp / k_impulse{0,1,7} 全部 case，单层 drain 隔离 + custom vs native exact
tests/qnn_kernel_e2e/correctness/test_w4a16_per_channel_chain1_e2e.sh

# 探额外 K lane 时覆盖 case 列表
W4A16_CHAIN1_CASES="default zp k_impulse0 k_impulse1 k_impulse7" \
  tests/qnn_kernel_e2e/correctness/test_w4a16_per_channel_chain1_e2e.sh

canonical chain8 的 accepted custom/HMX artifact 与 QNN native oracle 由仓库标准的 W4A16 per-channel profile flow 重建（输出落在 example/qnn_matmul_profile/output_w4a16_*_e2e_256/，该目录已 gitignore，属可重建产物）。 gate 定义见 Agent/current/qnn_kernel_e2e_ci.md。

6. 影响和边界

  • W4A16 的 Python reference 现在可以作为 native/HMX bit-exact oracle 使用。
  • QNN native raw output 仍是最终 correctness gate；Python 模型是已验证的解释模型和生成器 reference。
  • 这个结论当前限定为 v75 架构 + 当前 QNN 版本 + 当前 W4A16 HNH path。
  • W8A16/W16A16 若要修 Python reference，需要用同样的 zp / k_impulse 方法单独反推。
