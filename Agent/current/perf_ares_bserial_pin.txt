================================================================================
EXP1 钉死结论 (contention 坐实/否)
================================================================================
对照 (the kill):
  ARES feed_Σ 随 P +19.8% (P1->P4)  ===  CONTENTION 坐实 (gather/SMT 共享引擎串行化)
  pure wt-pack 随 P  +4.2% (P1->P4)  ===  ~无 contention (干净并行 producer feed)
  HMX 占用 (cbusy/cons) 两者都 ~flat (+14% / +7%) => HMX 不是瓶颈, 两者都 feed-bound。
  ARES b_serial(4-pt) 0.698M  vs  pure b_serial(4-pt) 0.415M  (差 ~0.28M)。

=> HA-c (contention 是 ARES b_serial 的主差异项) 部分成立但需精确措辞:
   - feed_Σ +19.8% 涨幅是 ADDITIONAL HVX work 被多线程"造"出来的 (gather 引擎争用/SMT
     issue-slot 争用), 这部分 NOT P-可约 => 它抬高了 effective K 而非直接进 b_serial。
   - b_serial 本身 (固定串行底, 4-pt 0.698M) 比 pure 0.415M 高 ~0.28M; 这 0.28M 才是
     ARES 真正"多出来的固定串行底"。
   - contention (feed +19.8%) 和 b_serial (+0.28M vs pure) 是两个独立信号: contention 进 K,
     固定串行底进 b。两者合起来才是 ARES 比 pure 慢 (2.528M vs 1.260M, P=4) 的来源。
   => 修正 doc "串行 merge-GLUE" 措辞: ARES 的劣势 = (1) feed work-volume 本就更大
      (W16 双-pass, P4 feed 9.07M vs pure 2.07M) + (2) 该 feed 有 +19.8% 的 P-contention
      (gather/SMT) 抬 K + (3) 固定串行底 b_serial 比 pure 高 0.28M。不是单一"串行胶水"。

================================================================================
最终归因 (3 实验合成) — ARES b_serial / contention 钉死
================================================================================
口径回顾: wall = K/P + b_serial. ARES P=4 wall 2.518M.
  K(4-pt LSQ)=7.259M, b_serial(4-pt)=0.698M (2-pt 0.794M; 4-pt 更分得开 contention 曲率 => 取 0.70M)。
  pure-HMX b_serial=0.415M => ARES 多出的固定串行底 = +0.28M。

两个独立信号 (别混):
  (A) b_serial = 固定串行底 (P-不可约 intercept) = 0.70M。
  (B) contention = feed_Σ 随 P +19.8% (P1 7.57M -> P4 9.07M) = +1.50M added feed @P4
      = ~0.375M wall-equivalent (/P=4)。它进 effective K, NOT b_serial。

三杠杆 cap-test 在 P=4 全 wall 上的占比 (有效上界):
  | 杠杆                  | EXP | Δwall (cap)  | wall-equiv | feed_Σ Δ | 性质                         |
  |-----------------------|-----|--------------|------------|----------|------------------------------|
  | (c) untile gather     | 2   | -4.24%       | 0.107M     | -4.6%    | gather争用+pack, 唯一干净杠杆 |
  | (b2) precise-diag fwd | 3   | -1.90%       | 0.048M     | -1.2%    | 大部分 SMT 藏住, 残漏 1.9%    |
  | (b1) HW-pack 残余      | -   | (=剩余)      | bulk       | -        | int16 kmajor byte-pack 不可约 |

=> ARES b_serial 0.767M(旧2-pt)/0.70M(本轮4-pt) 三成分实测:
   (b1) HW-pack int16 byte-pack = 主成分 (bulk, ~0.46M 量级, 与 analyzer/cron#84 'wt-pack
        非 gather-bound = HW 不可约 kmajor byte-pack' 结构侧一致; cap 不到=结构不可约)。
   (c)  gather-争用 = feed_Σ +19.8% 是真信号 (HA-c 坐实), 但它主要进 K 不进 b_serial;
        其中 untile gather 这一项 = wall 4.2% (0.107M wall / 0.104M feed-equiv), 是 (c) 里
        唯一能用 vxor 干净拿掉的子项。其余 contention (~0.27M wall-equiv) = W16 双-pass
        pack/depack gather + SMT issue-slot 争用, 非干净可消。
   (b2) precise-diag = 最小 (<=0.05M, wall 1.9%), 当前规模仍 MOSTLY SMT 藏住 (重验旧结论成立)。

HA-c (contention 是 ARES b_serial 主差异项) 裁定:
  ❌ 措辞需修正. contention 真实存在 (feed +19.8% 坐实) 但它进 K 不进 b_serial.
  ARES b_serial 的主差异项是 (b1) HW-pack (结构不可约), NOT contention.
  ARES 比 pure 慢 (2.518M vs 1.260M @P4) 的总账 = (1) feed work-volume 本就 4.4×
  (9.07M vs 2.07M, W16 双-pass) + (2) 该 feed 有 +19.8% P-contention 抬 K + (3) b_serial
  +0.28M. 不是单一"串行 merge-GLUE".

untile->vxor 唯一干净杠杆真值上界 = -4.2% wall (推翻 analyzer EST -5~12%; 偏乐观).
  即便完全消掉 untile gather, ARES P=4 2.518M -> 最好 ~2.41M, 到不了 2.2-2.4M 低端.
