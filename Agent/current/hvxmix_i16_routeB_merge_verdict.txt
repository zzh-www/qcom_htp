机理 (根因, 推翻 1.45× 前提):
  - 路 B int16 convhhh per-call = u8i8 的 ×11.5 (NOT ×1.45)。"1.45×" 是 pure-HMX 单 conv
    microbench 口径;在 K-stack 64³ merge 里 int16 dilate 做 4 byte-pass × 2× act/wt 字节 load,
    实测 ×11.5。
  - u8i8 时 consumer (1795/call, 70.8% 聚合) 完全藏在 producer DIAG (94.6% = 真 wall 驱动) 下
    (上一轮 cap-test: 去 consumer 买 ~0% wall)。
  - int16 时 consumer per-call 20583 -> MM/CONS 成主导, 4 个 producer SPIN 在它上 (聚合 217%),
    wall -> 4.59M。consumer 不再被吸收 = 假设破。
  - HMX 从不是 "93% idle 等吸收";它对自己被 11.5× 加重的串行链没有 headroom。

================================================================================
裁决
--------------------------------------------------------------------------------
命题 "wall 维持 + 精度收益" = ❌ 不成立。
  - wall: +126% (×2.26), 3 窗一致, MEASURED。
  - 精度: oc ~2.7× (3.10e-3->1.16e-3 端到端 / merge 级 280×), MEASURED (sim) / 方向设备确认。
  => 不是纯赚, 是 "精度 ×2.7 换 wall ×2.26" 的权衡; 对 wall 敏感的出货路线 = 否决。
根因 = consumer (HMX matmul) 不被吸收: 路 B int16 kernel per-call ×11.5 (NOT 假设的 ×1.45),
  把原本藏在 producer DIAG 下的 consumer 顶成主导, producer SPIN 爆炸。
  + producer feed wtpack ×2.4 (int16 pack 字节翻倍, 是 prompt 标的 "唯一真未知" 之一, 也涨)。
fallback (w16a8: wt int16 + act u8) 未测: 即便 act 省一半字节, consumer kernel 仍 int16 dilate
  (×11.5 主因来自 4-byte-pass + wt 字节, 非 act), 预计 wall 仍大涨; 建议交回 core 定是否值得测。
