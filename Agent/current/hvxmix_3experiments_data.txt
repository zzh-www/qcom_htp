EXP C (疑点2 反证) — consumer-free cap-test.  NEW gate=-DGDN_BR_CONS_STUB (default OFF, byte-unaffected).
  code: baremetal/src/gdnbm_imp.cpp ~1257, replace our_v73deep_kernel (consumer mxmem) with a SCALAR store
    (out garbage; pipeline path byte-identical otherwise).  口径: LOWER BOUND (consumer=0), T 错, wall-only.
  --- FIRST attempt (HVX-vector stub) was a methodology BUG: +55% slower.  Root cause = the HVX store on the
      consumer thread injects 5-on-4 HVX SMT contention (the PURE_HMX consumer is deliberately HVX-FREE).
      => secondary finding: the consumer staying HVX-free is LOAD-BEARING (any HVX work there = thrash).
  --- corrected (SCALAR-only stub, consumer stays HVX-free):
  win1: A=1842352 C=1847561  dWall=+0.28%
  win2: A=1826074 C=1800352  dWall=-1.41%

    window positive, spread > signal)
  VERDICT: 疑点2 CONFIRMED (反证成立) — removing the consumer matmul ENTIRELY buys ~0% wall (<=1%, noise).
    The consumer mxmem (~360 cyc/call, ~7% wall busy) is FULLY hidden under the producer feed; it is NOT on
    the critical path.  consumer-side total realizable space <= ~7% busy, ~0% wall.  360/call NOT worth touching.

EXP B (疑点3) — async SW-pipe recover spin.  NEW gate=-DGDN_BR_SWPIPE_KSTACK (default OFF, byte-unaffected).
  code: cross-block software pipeline over the KSTACK Sigma_k merge — dispatch block n async (no spin), prep
    block n+1's ACTIVATIONS (dependency-free; weights are forward-subst-dependent so fetched AFTER finalize)
    while the consumer runs n; then wait+depack n.  GdnSolveBR16.cpp off-diag loop (gated) +
    gdn_merge_kstack_dispatch/_wait_depack (GdnSolveBROp.cpp) + g_hmx_dispatch_async wt2-clear fix (gdnbm_imp.cpp).
  BIT-EXACT (the gate): async T vs sync T byte-identical, md5 ed9d5bcd... == ed9d5bcd..., cmp IDENTICAL, 3/3 runs.
    (2 bugs found+fixed en route, both proven by the bit-exact gate:
       1. g_hmx_dispatch_async never set jb->wt2 -> stale BP4 2nd-kernel ran -> T corrupt. fixed: jb->wt2=g_bp_wt2.
       2. effs[] as `static __thread` (vs stack local) -> wrong HVX-aligned read in gdn_pack_bias -> T corrupt.
          fixed: plain stack local (bias-pack consumes effs synchronously, need not outlive the call).)
  WALL:
  win1: A=1797198 C=1846437  dWall=+2.74%
  win2: A=1854537 C=1828814  dWall=-1.39%
  win3: A=1856767 C=1863089  dWall=+0.34%
  3-WINDOW MERGED: A_med=1854537 C_med=1846437  dWall=-0.44%   (INDISTINGUISHABLE from thermal noise; windows
    straddle zero, spread >> signal)
  TIMELINE (async vs sync, same renderer, 1 trace rep): SPIN-Σ 197950 (10.1% wall) -> 124567 (6.8% wall):
    the async DID hide ~37% of the spin (73K cyc absorbed under the act-prefetch).  But wall did NOT move.
  VERDICT: 疑点3 CONFIRMED (反证成立) — spin IS partly hideable (10.1%->6.8% wall-Σ) but recovers ~0% WALL.
    The spin was never on the critical path: producers are feed-bound on their OWN HVX; moving act-prep earlier
    just reorders the same HVX work, the producer's total HVX-busy (the real wall driver) is unchanged.
