临界路径序列 (一个 head 串行 stage 链, 重复 ×8 heads; 与 pre-FUSEDEP 同结构, 但 DEPACK 段被折掉):
  DIAG(对角块 fwd-subst, 串行递归)
    -> [off-diag MERGE: PREP(get_act QUANT/ACT + get_wt: PACK kmajor int16 双字节 + EFF)
        -> MM(producer wrapper: K-stack d-block gather + dispatch + SPIN-wait-HMX
              + FUSEDEP acc_add_surf 在 tiled 坐标累加, 无 per-block depack)
        -> REQ(widen+requant; FUSEDEP 末尾 untile 一次)] x (off-diag blocks)
    -> head store
  => 临界路 ≈ DIAG(串行) + Σ off-diag(PREP + MM-wrapper + REQ); HMX 真 MAC 仅 7.8% 嵌在 MM-wrapper。
  => 削掉的是 per-block DEPACK 阶段 (pre-FUSEDEP 独立 DEPACK Σ + per-block untile gather), 折进 acc。

### FUSEDEP vs pre-FUSEDEP 分解对照 (untile 削后) ###

口径说明 (诚实点): 任务简报给的 "pre-FUSEDEP = MM 31% / PACK 23% / DIAG 13% / QUANT 7%" 与 repo 内
  pre-FUSEDEP 权威 doc (Agent/current/timeline_hvxmixhmx.txt) 的数 (DIAG 31% of prod-Σ / merge-glue 60%
  / HMX 7% wall, 或 ASCII fine-view DIAG=26%/MM=17%/ACT=9%/PACK=7%) 不一致 —— 简报那组数更像本 W16_N8
  态自身的结构 (MM-wrapper 33% / PACK 28% / DIAG 21%), 不是通用 HVXMixHMX 基线。下面对照同时给两组,
  以 trace 实测为准。注意: repo 的 pre-FUSEDEP doc 是 SHIP 通用档 (PACK 仅 7%, 因 u8i8 单字节 wt),
  W16_N8 的 PACK 天然重 (int16 双字节 + d-block) —— PACK 占比的跃升是 W16_N8 档属性, 不是 FUSEDEP 引起。

  最关键的 FUSEDEP 结构变化 (untile 削后):
  1) DEPACK 阶段消失: pre-FUSEDEP per-block 有独立 DEPACK (Σ 96805 in 通用档) + 每 off-diag block 一次
     untile gather; FUSEDEP 把 depack 折进 gdn_w16n8_acc_add_surf (tiled 坐标累加, surf u16^zp 直接 sxt32),
     末尾整块只 untile 一次 (gdn_w16n8_untile_cv)。trace 实测: 本 FUSEDEP trace 中 stage 10(DEPACK) 与
     stage 6(ACC) 计数 = 0, 即这两段已被折叠/省去 d-1 次 untile gather。
  2) ACC 独立阶段消失: pre-FUSEDEP 的 int32 ACC 是独立 push; FUSEDEP 的累加发生在 add_surf 内, 不再单列。
  3) MM-wrapper 区相对变大 (33% of prod-Σ): 因为 acc_add_surf 现在跑在 MM-wrapper 区内 (dispatch 后立即
     在 tiled 坐标累加), 把原本独立的 DEPACK+ACC 活吸收进 MM-wrapper 的包裹时间。
  4) HMX 真 MAC 不变 (~7.8% wall, per-call ~393 cyc) —— FUSEDEP 不碰 HMX 路, 只削 producer 侧 untile。

  各 stage 现占 (FUSEDEP, producer-Σ):
    MM-wrapper 33% / PACK 28% / DIAG 21% / ACT 9% / REQ 5% / SPIN 3%
  -> MM 区 (含 FUSEDEP 折进的 acc): 33% of prod-Σ
  -> DIAG 区: 21% of prod-Σ (fwd-subst, 串行, 算法极, 削不动)
  -> PACK 现在临界路占比: PACK 28% of prod-Σ, 是第二大 producer 极 (仅次于 MM-wrapper); 在临界路 P3 行里
     PACK(K) 与 ACT(q) 交织贯穿整条 off-diag 链, 是 DIAG 之后的主要串行成本。

### 还有没有非结构成本可削 (诚实评估, 供 analyzer 下一杠杆) ###
  - PACK (28% of prod-Σ) = int16 weight kmajor 双字节 pack + d 次 per-block pack。是本 W16_N8 高精度档的
    内禀成本 (int16 weight 本就双字节)。是否可削属 analyzer 范畴 —— 候选: per-distinct-weight pack-cache
    (类比 pure-HMX 的 wt-cache, 消 merge 跨块冗余 T-weight 重打包) / d-block pack 复用。本 dev 轮只采 trace,
    未试任何削减。
  - SPIN Σ 仅 9.7% wall (Σ 口径), 即 producers 基本不在等 HMX (FEED-BOUND on 自己的 HVX 活), 削 spin 无大头。
  - HMX 7.8% wall, 大量空闲 —— 但 producer 的 PACK/ACT/DIAG/REQ 是 permute/quant/fwd-subst/widen, HMX 物理
    做不了 (与 pure-HMX cron#86 "HMX 吸收不了 HVX 活" 同理), 不能靠把活挪给 HMX 来削。
  - DEPACK 已被 FUSEDEP 削掉 = 本轮已兑现的非结构成本削减 (untile d-1 次 -> 1 次)。

地板判定 (本 dev 轮不下结论, 仅供 analyzer): wall ≈ 3.20M 的临界路 = DIAG(串行 21%) + merge-glue(75%,
  以 MM-wrapper 33% + PACK 28% 为两大极)。下一可削候选 = PACK (W16_N8 内禀双字节, 需 pack-cache 类杠杆,
  analyzer 评估); DIAG 串行是算法极。
