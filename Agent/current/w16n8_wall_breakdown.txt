===================================================================================
[D] 一句话主因 + 归因总结
===================================================================================
  ★ wall +48% (多出 ~0.93M) 主因 = PACK 翻倍, 且其中 act-pack 是 weight-pack 的 ~2x。
    具体: W16_N8 是 int16 高精度档, weight 与 act 都是双字节 (u8i8 单字节), kmajor/crouton
    vgather pack 量天然翻倍, 且 n8 是 d 次 per-block pack。cap-off 实测 W16_N8 PACK 对 wall
    贡献 ~935K (act ~776K + wt ~377K, 有重叠), 与 +48% 多出的 ~0.93M 同量级、同因果方向。

  逐 stage 归因 (与任务简报预期对照):
    [预期 PACK 翻倍 = 最大头]  ✅ 坐实: PACK Σ 678K(u8i8) -> 2.25M(W16) = 3.3×; cap-off wall ~935K
        = +48% 主因。act-pack(~24%w) > wt-pack(~12%w), act-HEAVY (推翻 weight-heavy 估计)。
    [预期 cv 累加 (n8 d 次单块 + int32 acc)]  → 已被 FUSEDEP 折进 MM-wrapper 桶 (独立 ACC/DEPACK
        stage 计数=0); 体现在 MM-wrapper 比 u8i8 MM/glue 多 ~2.0M Σ 里, 是第二影响但被并入 glue 桶。
    [预期 REQ (int16 widen+requant)]  🔴 实测 W16 REQ Σ 506K < u8i8 902K (REQ 反而更少, 因 FUSEDEP
        末尾 untile-once 把 REQ 集中收口; u8i8 per-block requant 反而 Σ 更大)。REQ ≠ +48% 来源。
    [预期 DIAG int16 多]  🔴 实测 W16 DIAG 2.49M ≈ u8i8 2.64M (基本持平, W16 略少)。DIAG ≠ +48% 来源。
    [HMX MAC 两侧 FEED-BOUND]  ✅ 核对: W16 CONS 9.0%w / u8i8 6.2%w, 都 < 10%w, HMX 真 MAC 非主因
        (per-call W16 594 vs u8i8 416 cyc, 量级一致; HMX 都大量空闲)。

  净结论: W16_N8 比 SHIP u8i8 慢 +48% 的钱几乎全花在 ★PACK★ (int16 双字节 + d-block per-block pack,
    act-pack 为主), 外加 FUSEDEP-glue (cv 累加/depack 折进 MM-wrapper) 的次级开销; DIAG/ACT/REQ
    W16 反而不比 u8i8 多 (甚至略少), HMX MAC 两侧都闲不是瓶颈。
    -> 这是 int16 高精度档的内禀成本 (双字节 pack); act-cache 已削掉 7 个冗余 act-pack (−19.5% wall,
       3.57M->2.87M), 剩下的 PACK = 不可约 wt-pack + 9 distinct act-pack, 是结构地板 (cron#84 判
       wt-pack 非 gather-bound = HW 不可约 kmajor byte-pack)。再降需精度/算法权衡。
