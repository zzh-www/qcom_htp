# What changed today

Building on the `v8_c8_bias_combined_static_2026-04-27` and
`bias_to_vtcm_decoded_2026-04-27` work, today we **switched the bias
bytes inside the combined-static buffer from V8-prod-simple to native-fold**.

## Before
- gen_v8c8_test.py wrote V8-prod simple bias: 32 × (fp16 scale, fp16 baseline=0x4000) per tile = 128 B used + 128 B zero-padding = 256 B/tile.
- Lower 128 B contained the per-channel (fp16 scale, 0x4000); upper 128 B was unused (left zero by `np.zeros` init).

## After
- gen_v8c8_test.py now writes **native ConvLayer bias_to_vtcm format**: 256 B/tile fully populated.
- Lower 128 B unchanged (V8-prod fp16-pair encoding — same byte format).
- **Upper 128 B now carries 32 × int32 effective_bias[c]** = `-ACT_ZP × Σ_k W[k,c] + bias_q[c]` (the weight-aware fold).

This is the **byte-identical layout** we RE'd from the native ConvLayer test (`Agent/qnn_re/bias_to_vtcm_decoded_2026-04-27.md`).

# What this proves

The **end-state in VTCM is now byte-1:1 with native ConvLayer's bias_to_vtcm output**. When the HMX kernel body is wired up, it can apply the native HMX bias-load instruction sequence (probably one `mxmem` for the fp16 pair + a separate accumulator init from the int32 fold) and consume RAW u8 activation directly — no upstream centering needed.

This unlocks the cleanest path to bit-exact native equivalence:
- Activation: raw u8 from QNN's `ForceFormat_Crouton` (no per-element zp subtraction in our op).
- Bias: native fold layout already in VTCM (this work).
- Weight: native ConvLayer K-tile / N-tile / 4-row-group / 1024-byte tile layout (already done in `v8_c8_alignment_phase2_BREAKTHROUGH`).
- Kernel body: same MAC + `:cm:sat.ub` as V8 prod, but reads bias VTCM in native format.

# Side note: native cross-check fit

Re-running the native ctx-bin decode at offset `0x19180` with `bias_scale = 6.31e-5` shows:
- ch0..7: within ±2 LSB of formula
- whole 256 channels: only ~7/256 strict ±1 LSB (max diff 72)

Yesterday's note claimed 256/256 ±1 LSB. The discrepancy is likely a per-channel `bias_scale` (vs the per-tensor 6.31e-5 fit) — quantization of the quasi-symmetric MatMul produces per-channel scales. **Doesn't affect today's deliverable**: our generated bytes ARE correct for any chosen `bias_q` and `act_zp`; the native ground-truth fit just needs better calibration if we want strict cross-check across all channels.

```bash
cd example/hmx_matmul_phase3

# Inspect bytes in produced ctx-binary
python3 -c "
import numpy as np, onnx
from onnx import numpy_helper
ROOT='phase1_validation/v8c8_test'
ctx=open(f'{ROOT}/ctx/v8c8_ctx.bin','rb').read()
m=onnx.load(f'{ROOT}/v8c8.onnx')
combined=numpy_helper.to_array(next(t for t in m.graph.initializer if t.name=='wt_bias')).astype(np.uint8).flatten()
pos=ctx.find(combined[:512].tobytes())
WT=65536
fold=np.zeros(256,np.int32)
for t in range(8):
  s=pos+WT+t*256+128
  fold[t*32:(t+1)*32]=np.frombuffer(ctx[s:s+128],np.int32)
wRaw=np.load(f'{ROOT}/v8c8.onnx.wRaw_KN.npy')
bq=np.load(f'{ROOT}/v8c8.onnx.bias_q_int32.npy')
exp=-128*wRaw.astype(np.int32).sum(axis=0)+bq
print('256/256 match:', np.array_equal(fold, exp))
"
```
