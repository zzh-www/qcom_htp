## 重大结论：Gap 不在 dispatcher inputs 上

我们已经 match native 的：

| 字段 | Native | 我们 |
|------|--------|------|
| Kernel selector (CTRL) | 8 (8-bit) → dispatch to v73 bbb 家族 | 直接 dlsym v73 deep |
| extra_param[0..1] | [1, 0] | [1, 0] ✓ |
| Mask buffer | set_hmx_params_conv1x1(0x70b, 0,0,0, 0x20) per V9_DESC_DUMP probe | 一样 ✓ |
| od / ad fields | n_tiles_pow2=64, k_total=256, n_act=8 | 一样 ✓ |

**所有可见的 dispatch 输入都对齐了。但我们仍 747 packets vs native 346。**

## Gap 还能在哪？

排除项：
- ❌ Kernel selection (CTRL=8 → 同一 kernel 家族)
- ❌ extra_param 值
- ❌ Mask buffer 字段
- ❌ od/ad 描述符字段

剩余可能：
1. **HMX internal state** — native 在 dispatch 前发了 HMX state-config
   packets（HMX descriptor registers），让后续 mxmem 行为不同。我们 dlsym
   直接调跳过了这一步。Per `docs/hmx-programming-guide/01-mental-model.md`
   "descriptor-driven HMX" 模式。
2. **Native 实际调的不是 `hmx_v73_convbbb1x1deep_stride1`** — CTRL=8 dispatch
   后内部可能选了一个我们没识别出的 kernel symbol。比如 `hmx_v73_convbbb1x1_stride1`
   non-deep body（不走 deep variant 跳转）—— 但那个 body 也用 `:deep:cm` 测过比 deep 还慢。
3. **Schedule pattern** — native 的多个 ConvLayer_s1.opt 实例可能 share
   HMX state 不重新初始化，从第 2 个 matmul 开始 packet 数显著降低。但
   chrometrace 里 MatMul_1..MatMul_7 都是 ~346 packets 跟 cold MatMul_0 的
   ~346 一致（cold 是 cyc 高 cpp=12.9，但 packet 数相同），所以不是状态共享。
